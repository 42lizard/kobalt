# Native validation

Use the installed Qt 6.11.3 SDK. Configure once as described in [Building](building.md#mac). Run the commands below from `platforms/desktop/`. They use this checkout's code, assets and incremental cache. No device, firmware, Python or private service is required.

## Everyday commands

| Task | Build | Run or output |
| --- | --- | --- |
| Fast checks | `cmake --build --preset mac-fast-tests` | `ctest --preset mac-fast` |
| All native checks | `cmake --build --preset mac-tests` | `ctest --preset mac` |
| Integration checks | `cmake --build --preset mac-tests` | `ctest --preset mac-integration` |
| Screenshot gallery | `cmake --build --preset mac-screenshots` | `build/screenshots/mac/index.html`, relative to the repository root |
| Interactive app | `cmake --build --preset mac` | Open `build/desktop-mac/Kobalt.app` manually |

Use `ctest --preset mac -N` to list registered tests. Use `-R` to select a test name or `-L model`, `-L engine`, `-L session` or `-L desktop`, `-L resource` or `-L component`, `-L ui`, `-L platform` or `-L corpus` to select a group. CTest does not build tests automatically. A failed test prints its assertion and captured output. CTest keeps the latest run in `build/desktop-mac/Testing/Temporary/LastTest.log`.

Model, engine, session, resource, lifecycle and component test names have the corresponding prefix, for example `session.reader-session`. Desktop checks have the `desktop.` prefix. The 33 fast checks and 103 integration checks are disjoint; the full preset runs all 136. The 26 model checks use synthetic inputs and include no timed network-stall tests. Resource integration checks use local controlled servers, with no external service. The standalone checks preserve the restored assertions from `develop`, with documented setup adaptations and additional regressions for discovered failures. They link existing portable core objects through one archive rather than compiling another application implementation. Desktop UI objects stay separate, so UI edits do not relink the portable standalone checks. Component checks link the existing UI objects. The restored component suite uses Fusion, matching the app. Test geometry models share exactly the window's font inputs because CREngine uses one font manager per process. Page-tap helpers preserve the original pixel center and choose exposed paper when a panel covers it.

The restored `reader`, `publisher-markup`, `local-reader` and `document-word-count` checks retain all 738 original assertion calls. Their focused EPUBs are generated offline in C++ with the original text, span IDs, markup and resource paths. The document-cache matrix has its own integration check so the reader check stays within the existing child deadline under parallel execution. It checks parsed/cached pixel equality, chapters, changed typography, Bionic modes, fingerprints, cache policies and obsolete entries. The reader check also links the portable Kobo position codec; it does not load Nickel or inspect firmware symbols. Its variable-font cases require the pinned Amstelvar fixture rather than silently skipping them. Intentional cache-policy and stylesheet mismatches can print CREngine cache warnings in these negative tests; the normal-book diagnostic check still rejects unexpected warnings.

The lifecycle executable preserves all 717 assertion calls from 39 selected methods in the former `tests/native-ui/reader_test.cpp` at `82b8935`. It links the existing production reader, session, book and canvas objects. Controlled host services supply battery, rotation, progress and presentation callbacks. The public position codec runs natively; these tests do not load Nickel or check firmware symbols. The new executable is a dependency of `mac-tests`, but not `mac-fast-tests`. Run `ctest --preset mac -L lifecycle` for this group. Every registered case has the existing 30-second parent deadline and its own profile. No timeouts were raised.

General lifecycle and preview checks use Type Tester. Focused cover cases generate the original 128 × 64 cover with a large PNG text chunk, outside the first page. Coverless and native-position cases use the original EPUB text and span IDs. These fixtures are generated offline with the same deterministic ZIP writer as the desktop checks. Sensor registrations, paused workers and publication resources are released after each case.

The touch-rotation check compiles the production Qt5 input adapter against native Qt, without rebuilding the reader. It preserves the original orientation, bounds, transform-scope, ownership-release and malformed-version checks. The device guard now rejects Clara HD, including firmware 4.38.23828 from [discussion #48](https://github.com/nicoverbruggen/kobalt/discussions/48), and retains the correction for Clara BW and Clara Colour. Unaffected devices keep the native transform in all four orientations. This check does not exercise a physical touch controller.

Basic missing-file, cancel/open and reopen checks already run through the actual desktop controller; their old test-host copies are not restored. The old scroll-only test canvas is replaced by the production graphics canvas. Frontlight-specific navigation rows remain with platform adapter work. The selected paint-region, annotation-frame, font-source, orientation and literary checks now run in the groups above. Broader platform and corpus coverage remains deferred.

## Book fixtures

General desktop reading checks, diagnostics, feature interactions and screenshots use `tests/fixtures/trevelyans-type-tester.kepub.epub`. This is [Trevelyan's Type Tester v1.2](https://github.com/nicoverbruggen/type-tester-epub/releases/tag/v1.2), a public-domain typography test book. The fixture includes a CSS correction to keep each chapter label and its following title together: `h2.chapter-num` has `break-after: avoid`, and `h2.chapter-num + h1` has `break-before: avoid`, with their `page-break-*` equivalents. Only `OEBPS/styles.css` differs from the upstream KEPUB's contents. The SHA-256 checksum is `1050bc7af6a6b19267319c8b56965ca7cbf63abedfa8079ab5c4eacbb6c407ac`; CMake verifies it before building the desktop checks.

The book is checked in, so testing needs no download or another checkout. Screenshots include the book's cover and narrative text. Synthetic books remain for focused session, malformed-input and stylesheet regressions where controlled content is necessary. Passing this real-book check does not replace a broader publication corpus.

The optical-size and engine reader checks also use `tests/fixtures/AmstelvarAlpha-VF.ttf` from [Google Fonts revision c62e1a5](https://github.com/google/fonts/tree/c62e1a5a52eb5dc1d2fdf7cea8d4fa859c40180f/ofl/amstelvaralpha). Its SIL Open Font License is stored beside it in `AmstelvarAlpha-OFL.txt`. The unmodified 128,312-byte font has SHA-256 `8064db0a8d839ae41296252291acb8e4deffab64dddfb55485b0180420568626`, verified by CMake. The desktop test copies it into its isolated profile, selects it through the real picker, changes optical size without changing text size and reopens the book to check persistence. The engine test checks real weight-axis rendering, independent thickness, optical size, saved settings and invalid values with the same font.

## Restored input, paint and adapter checks

The 14 UI checks and two additional reader-window checks retain 210 selected assertion calls from `tests/android/android_ui_test.cpp` and `tests/native-ui/reader_test.cpp` at `82b8935`. The UI checks run the production graphics canvas for input delivery and the production widgets for pixel and paint-region assertions. The toolbar invalidation check measures the reader window directly: a graphics proxy renders widgets into its display cache, which adds paint events without proving that the reader invalidated those widgets. The annotation-frame matrix uses the original focused EPUB text and anchors, including saved, draft, absent and 256 off-page highlights. It checks the first complete frame while turning pages and reflowing. General reading checks and screenshots still use Type Tester.

The eight platform checks preserve their original assertions with path and fixture adaptations. Font-source precedence uses the pinned Amstelvar font, whose family is absent from the bundled reader catalogue; using bundled Bitter would test duplicate-family precedence instead. System-font checks use synthetic plain, compressed and encrypted wrappers in temporary directories. Session dispatch and refresh submission use controlled callbacks, not firmware symbol resolution or physical devices. The orientation matrix retains the production debounce and stays outside the fast lane.

The literary corpus restores unchanged source JSON for Arabic, Hebrew, Hindi and Japanese from the original fixture set. `tests/fixtures/public-domain/catalog.json` retains their original file checksums, and the test verifies the source files and chapter checksums. It packages the first eight paragraphs of each of the first two chapters in C++, with original text, author, source revisions, rights and Wikisource contributor attribution. The source works are public domain; the transcriptions retain the CC BY-SA 4.0 terms in the accompanying `LICENSE` and EPUB metadata. The test checks actual bundled script glyphs and selects a word inside a searched range; a multiword range center can be whitespace. This bounded corpus is not the original 16-language corpus or a full international rendering guarantee.

Deliberately excluded: duplicate opening/reopening workflows, the retired scroll-only canvas and Python tooling tests, exhaustive cosmetic permutations, and the word-count benchmark. Linux framebuffer animation submission, remaining Nickel adapter behavior, Android/BOOX-specific checks and the full multilingual corpus remain separate work. No Mac SDK shims are added for Linux framebuffer APIs. Public firmware compatibility checks remain deferred.

## Screenshots

The screenshot preset builds the current code and produces 133 PNGs, a checksum manifest and a local HTML gallery. The gallery can filter filenames and open full-size images. Outputs replace the previous complete set only after every capture succeeds. A failed run preserves the previous complete set. The generator refuses to replace an unrelated directory.

Each light/dark variant of Fill window, six-inch and seven-inch mode captures the cover, reading, menu, chapters, statistics, text controls, font picker, layout, header/footer presets, a bookmarked page, bookmark list, bookmark-removal confirmation, annotation list, search results, settings, About, annotation mode, selection start, annotation actions, a saved highlight and saved-highlight editing actions. There is one startup capture per device mode. Fill window also captures Dictionaries and UI settings; those tabs must be hidden in the device previews.

The book fixture and clock are fixed. Screenshot profiles reload bookmarks with a fixed creation date before capturing the list and confirmation. Dictionary screenshots use a fixed 32 GB of free space instead of querying the development disk. Capture delivers pending layout and paint events before rendering the visible frame. Host Qt rendering can still affect pixels, so compare runs with the same environment. The manifest records image dimensions and SHA-256 checksums, book identity and checksum, application version, Qt version, source commit and modified status. Equal inputs should produce equal images. Compare manifests to detect changes, then inspect the affected images. No golden images are checked into the repository, and image equality does not establish functional correctness. The integration tour also verifies chapter navigation, font and size application, bookmarking and search-result navigation through the real controls.

## Temporary files and timing

All native checks and screenshot runs use private working and temporary directories under `build/desktop-mac/test-tmp/`. The CMake parent removes those directories after success, failure, signal termination or its 30-second timeout. Desktop fixtures drain the reader before removing their profiles. Screenshot staging stays inside the parent-owned temporary directory. If replacing a complete screenshot set fails and rollback also fails, the previous set remains outside that directory and the error names its location. Keep the current screenshot set, latest useful failure evidence and incremental caches.

Measure with `/usr/bin/time -p` around the commands above. Report the first build of restored targets separately from an unchanged build. A dependency recipe or patch change currently invalidates the complete dependency set; application-only changes reuse it. Do not compare different test inventories or SDKs as a measured speedup. Linux execution has not yet been validated with a matching prepared SDK; the test sources and cleanup launcher avoid Mac-only test logic where possible.

The earlier engine-restoration build took 28.43 seconds with existing application objects and dependencies; it compiled test sources and refreshed build metadata rather than rebuilding the engine or Qt.

Earlier, three consecutive screenshot runs with the corrected Type Tester fixture, fixed bookmark dates and fixed dictionary free space produced identical manifests and image checksums. The current run produced all 133 images. All 127 images outside About match the previous pixel checksums; the six About captures include the updated source commit. Light and dark annotation captures and the About screen were inspected.

The Qt5 package passed ZIP integrity checks and contains the ARM32 library at `usr/local/Kobo/imageformats/libkobalt.so` in `KoboRoot.tgz`.
